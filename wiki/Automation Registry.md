## About

> Automation is fragmented across schtasks, Claude hooks, ad-hoc Python -- no single place to see what's automated and on what mechanism.

**Customer:** Operators (catalog + audit + toggle automations), [[Dream]] (UI tab consumer at AR-S10)

**What it does:** Single registry for all ecosystem automations. Entries declare a mechanism (cron / claude_hook / claude_loop / manual / executor / claude_check / claude_blocker_callback). Catalog only -- dispatches via the right backend, delegates execution to the right app. Schema v1 documented at docs/proposals/automation-registry-schema-v1.md.

**Out of scope:** Executing the work itself (each mechanism's backend handles that -- `executor` delegates to automation/ at :5045; `cron` runs schtasks/launchd/systemd; `claude_hook` runs in active Claude Code sessions; etc.). Storing schedules (Calendar does that). Lifecycle / work tracking (Pipeline Dashboard does that).
